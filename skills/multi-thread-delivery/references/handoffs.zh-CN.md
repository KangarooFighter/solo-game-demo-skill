# 可复用任务单与交接

用于首次启动、接口变更和恢复。字段按风险裁剪；短任务可把几项合成一段，不机械地产生一套文档。优先使用现有项目载体；禁止项目内改动时只保存在统筹对话或用户指定的外部位置。以下是消息模板，不是必须创建的文件树。

## 当前状态摘要

```text
项目／本轮：项目标识、轮次、当前目标、有限终点
授权：允许实现／环境操作／本地版本操作／外部发布；未知项注明未知
规则：保留什么、替代什么、不做什么
基线：真实提交或相关文件指纹；有未提交改动时说明归属
角色映射：职责 → task_id / host / 实际工作目录或工作树
任务：ID@revision | owner | 状态 | 输入契约 | 可写路径 | 依赖
共享资源：资源 → 持有人 / 使用范围 / 释放条件
有效证据：对象版本 → 验证范围 / 结果 / 原件位置 / 限制
下一动作：执行者 / 已满足条件 / 尚缺授权或外部依赖
```

摘要更新当前事实；历史引用不与当前持有人、冻结条件混写。使用自然语言角色名也可以，不必固定中文编号。另一个项目不得继承这份摘要的 task_id、路径、远程或权限。

## 任务单

```text
任务：PROJECT-TASK@revision
目标：使用者可观察到的结果
背景：本轮必要决策和输入引用，不复制整个聊天历史
环境：项目／实际目录或工作树／输入基线与接口修订
允许修改：精确文件、目录或独立产物
禁止修改：用户改动、公共入口、其他角色所有区域
依赖：等待哪一项产物；等待期间可以先完成哪部分
验收：核心成功路径、相关失败路径、需要的交付形态
已授权的后续动作：条件 A/B 满足后可做 C；不包含的外部动作
失效条件：哪些需求／接口／基线变化需要先与统筹重新确认
回报：改动、真实运行与退出、产物路径、限制、资源释放、下一接手者
```

## 状态和事件

推荐任务状态：待开始 → 执行中 → 待验收 → 完成；执行失败或缺外部条件标阻塞；被新规则取代标已替代。缺少共享设备是依赖，不等于整个项目失败。状态要伴随下一动作，不能只有一个“blocked”。

消息建议头部：`任务 ID@修订 | 事件 | 接收方`。事件可以是 `STARTED / READY / HANDOFF / BLOCKED / CONTRACT_CHANGE / DONE`，不是需要安装的协议或产品原生命令。

```text
GAME-ASSETS@2 | HANDOFF | 02
已完成：图标与三种状态资源，接口仍为 UI-2。
证据：实际产物路径、预览、检查结果及其范围。
基线：本次资源指纹；未改公共入口。
资源：已停止预览进程并释放原约定设备。
下一步：按先前授权，02 可接入指定组件并运行相应集成检查。
限制：尚未做窄屏与键盘集成验证，由02接入后检查。
```

接收方沿先前授权执行即可；不要求发送方再重复一句“正式批准”。无充分授权时明确缺的是哪一个动作的权限，不向所有参与者泛问“能继续吗”。

## 变更与恢复

```text
本轮修订从2升至3：新需求改变什么；不变的约束是什么。
受影响任务：ID列表；旧交付是否可继续用、需局部返工或已替代。
共享文件：原owner需停写哪些范围；接手者何时可以开始。
证据影响：复用哪些未变检查；重跑哪些实际受影响检查。
继续权限：已授权且仍有效的动作；必须暂停的外部动作。
```

恢复消息只附当前摘要与差异：上次真实完成到哪、当前观察到什么、下一条有限操作是什么。不要在未核实前硬写“上轮已成功”。新输入打断工作时，先区分取代需求、追加需求或只是询问状态。

## 可以直接使用的启动语句

新建用户可见任务，需用户明确表达创建意图：

> 使用 $multi-thread-delivery 启动我的项目。当前对话做统筹，请创建其余三个独立任务分别负责实现、专业产物、验证发布；若此项目已有对应任务就复用。项目位置与目标如下……。保持已有目录结构，先明确可写范围、接口、验收和条件式交接，再开始工作。

复用现有团队迭代：

> 使用 $multi-thread-delivery 组织下一轮，复用这个项目已有任务，不新建窗口。本轮要改变……，必须保留……，不做……。按影响范围更新分工和验收，满足已授权交接条件后继续，最后交付实际可用结果。

只优化流程、不执行项目：

> 使用 $multi-thread-delivery 审阅我们的协作方式，只输出角色、任务单和交接改进，不创建任务、不修改项目文件、不触发发布。
